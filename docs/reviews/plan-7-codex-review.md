### A — literal proposed miner and detector predicates

The driver calls the real `mineIds` for the unchanged pattern pass, preserves its early return at `max`, and then executes the plan's rule loop. Its essential rule pass is:

```js
for (const rule of settings.ids.rules ?? []) {
  for (const text of rule.source === 'branch' ? [branch] : texts) {
    if (typeof text !== 'string') continue;
    for (const m of text.matchAll(new RegExp(rule.pattern, (rule.flags ?? '') + 'g'))) {
      if (settings.ids.stoplist.includes(m[0].split('-')[0])) continue;
      out.add(rule.normalize
        ? rule.normalize.replace(/\$(\d)/g, (_, i) => m[+i] ?? '')
        : m[0]);
    }
  }
}
```

No demonstrated injection remains under that rule. Test malicious IDs, empty validated input, invalid-ID counts and returned keys outside the requested set. Do not fall back to an unbounded search after all keys are rejected. `+` in the project-key portion also excludes one-letter keys; document the supported key grammar rather than silently broadening it during escaping.

### GitHub

`Issue.stateReason`, `Issue.closedAt`, `PullRequest.headRefName`, `PullRequest.mergedAt` and `PullRequest.mergeCommit` are correctly named. **PullRequest has no `stateReason`.** Use `issueOrPullRequest(number:...)` with type fragments to distinguish the shared issue/PR numbering space. `COMPLETED` means completed; `NOT_PLANNED`, `DUPLICATE`, `REOPENED` or null must not become delivered. [Issue fields and enums](https://docs.github.com/en/graphql/reference/issues), [repository lookup](https://docs.github.com/en/graphql/reference/repos), [PR fields](https://docs.github.com/en/graphql/reference/pulls).

The listed `gh pr list --json` fields exist. D-DELIVERY requests `title`/`mergeCommit`, but Task 3's command drops them; settle the metadata needed for verification and avoid retaining unnecessary title text. [CLI fields/selectors](https://cli.github.com/manual/gh_pr_list).

`gh api graphql -f query=...` is valid and delegates authentication to gh. One hundred aliases is a client batching choice; it is not ordinary connection pagination. Bound any selected label connection and handle API errors explicitly. Tokens can come from gh login or its documented environment variables; the plan therefore promises **env or CLI-managed credentials**, not literally env-only credentials. Keep secrets out of query arguments and diagnostics, disable debug output in tests, and pin repository/host selection. [gh API command](https://cli.github.com/manual/gh_api), [gh environment and auth precedence](https://cli.github.com/manual/gh_help_environment).
